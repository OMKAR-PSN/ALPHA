## Overview

SatQuery AI is an intelligent vision-language agent that allows users to ask natural-language questions about satellite imagery. The agent interprets the query, decides which remote-sensing tools to use, and dynamically orchestrates the analysis pipeline — meaning users never need to manually specify models, preprocessing steps, or toolchains.

```
USER QUERY
    ↓
CENTRAL CONTROLLER  (understands, plans, selects, orchestrates)
    ↓
SPECIALIST TOOLKIT  (analyses images, detects change, classifies, fuses, reconstructs)
    ↓
CONFIDENCE + EVIDENCE CHECK
    ↓
GROUNDED NATURAL-LANGUAGE ANSWER
```

---

## Features & Highlights

- **Live Processing on Real Satellite Data:** Demonstrates live execution of remote-sensing algorithms (e.g., cloud masking, bi-temporal change detection) on real Sentinel-2 L2A optical and Sentinel-1 SAR imagery.
- **Dynamic Cloud Reconstruction:** Automatically detects cloud coverage and triggers SAR-guided reconstruction if contamination exceeds acceptable thresholds, without requiring user intervention.
- **Confidence-First Architecture:** Every specialist tool outputs a statistical confidence score. The agent detects cross-tool disagreements and factors data provenance into its final evidence grading.
- **Full Provenance Tracking:** A rigorous lineage system tracks whether an output was generated by a live algorithm or a fallback heuristic, ensuring complete transparency for analysts.

## Quick Start

### Prerequisites
- Python 3.10+
- Node.js 18+

### 1. Install Backend Dependencies
```bash
pip install fastapi uvicorn python-multipart pillow numpy opencv-python-headless scikit-image
```

### 2. Start the Backend
```bash
python -m uvicorn backend.main:app --host 0.0.0.0 --port 8000 --reload
```

### 3. Install & Start the Frontend
```bash
cd satquery-ai
npm install
npm run dev
```

### 4. Open the App
Navigate to **http://localhost:5173**

## Specialist Toolkit

Every tool implements `BaseTool` and returns a standard `ToolResult`. Provenance is strictly managed to differentiate live execution from simulated fallbacks.

```python
{
  "tool_name": str,
  "status": "success" | "warning" | "error",
  "confidence": float,
  "result": dict,
  "visual_output": str,  # base64 PNG
  "execution_mode": "LIVE_ALGORITHM" | "SIMULATED",
  "input_provenance": "REAL_SATELLITE_DATA" | "SYNTHETIC_DATA"
}
```

| Tool | Purpose |
|------|---------|
| `image_validation` | Format, alignment, metadata checks |
| `cloud_detection` | Cloud coverage analysis |
| `cloud_reconstruction` | SAR-guided infilling of cloud-obscured pixels |
| `scene_understanding` | Scene type + dominant land-cover classification |
| `object_region_detection` | Feature localisation with bounding boxes |
| `land_cover_classification` | Pixel-level classification |
| `bi_temporal_change_detection` | Change map + statistics |
| `sar_optical_fusion` | Cross-modal reasoning + conflict detection |
| `spatial_reasoning` | Distance/adjacency/buffer analysis |
| `evidence_comparison` + `confidence_check` + `answer_synthesis` | Final grounding |

## Key Design Decisions

### Separation of Concerns
```
LLM / Controller:     UNDERSTAND → PLAN → SELECT → ORCHESTRATE → EXPLAIN
Specialist Tools:     ANALYSE → DETECT → CLASSIFY → FUSE → RECONSTRUCT
```

### Event-Driven Streaming
The backend architecture leverages Server-Sent Events (SSE) to stream the tool execution trace to the frontend in real-time, providing transparency into the agent's decision-making process.
